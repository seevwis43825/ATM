# 产品路线图（Roadmap）

> **状态**：评审中 · **所有者**：产品 · **版本**：v1.0
> **最后更新**：2026-10-01
>
> **口径**：本路线图是产品目标，不是发布承诺。状态应以当前源码和实际 Issue/PR 为准；日期、负责人和生产指标需由团队评审后确认。

---

## 1. 目的

- 让团队对未来 3-6 个月的工作有清晰共识
- 让利益相关方（监管、客户、合作方）看到演进方向
- 让新人快速理解当前阶段与目标

---

## 2. 当前阶段

**Current：本地研发/演示基线**

已具备 .NET 8 模块化单体、Host + MockBank 双进程、四插件、SQLite、认证/人工确认/审计和 149 个 UnitTests。Transfer 支持模拟转账；BillAnalysis、CardManagement、Wealth 已有当前能力，但 Wealth 仍是只读产品/推荐/余额查询。默认使用规则意图识别，可选 LLM；尚无生产部署、真实 CBS、完整前端或合规认证。

**下一步目标**：先以 Issue/PR 验证每项工作，再更新“完成/上线”状态。

## 3. 季度路线图（Target）

### 3.1 Q4 2026（v0.4 - v0.6）：核心场景闭环

| 模块 | 工作项 | 负责 | 状态 |
|------|--------|------|------|
| **转账** | 智能收款人推荐；转账撤销/退款；行内转账 | 业务 | 待 |
| **账单** | 自动账单解析（邮件/短信/微信）；账单分类 | AI | 待 |
| **理财** | 风险测评；理财推荐 v1（保守型） | AI + 业务 | 待 |
| **卡片** | 卡片激活、挂失、查询 | 业务 | 待 |
| **合规** | 用户同意管理；HITL 审批工作台 | 安全合规 | 待 |
| **基础设施** | LLM 国内双供应商；监控告警 v1 | 平台 | 待 |

**关键里程碑**：
- M0.4（10 月底）— 智能转账 + 行内转账上线
- M0.5（11 月底）— 账单分析 + 卡片管理上线
- M0.6（12 月底）— 理财 v1 + 跨场景联动（转账后推荐账单分类）

### 3.2 Q1 2027（v1.0 - v1.2）：合规达标 + 体验提升

| 模块 | 工作项 | 负责 | 状态 |
|------|--------|------|------|
| **合规** | 算法备案；PIA 全面执行；监管报送接口 | 安全合规 | 待 |
| **场景** | 订阅/代扣管理；智能客服升级 | 业务 + AI | 待 |
| **AI** | 多 Agent 协同（TrA + F05 TradingAgents 思路） | AI | 待 |
| **记忆** | 用户长期记忆（多轮对话/跨场景） | AI | 待 |
| **运维** | 灾备切换演练；性能优化 | 平台 | 待 |
| **体验** | 移动 H5 / IM 双通道打磨 | 前端 | 待 |

**关键里程碑**：
- v1.0（1 月底）— 6 大场景全部上线，可对外发布
- v1.1（2 月底）— 算法备案完成，合规达标
- v1.2（3 月底）— 用户记忆 + 跨场景联动 v1

### 3.3 Q2 2027（v1.3 - v1.5）：智能化 + 规模化

| 模块 | 工作项 | 负责 | 状态 |
|------|--------|------|------|
| **AI** | 自适应学习（在线学习用户偏好） | AI | 待 |
| | 主动建议（基于场景感知） | AI | 待 |
| | 复杂任务规划（Multi-step Plan） | AI | 待 |
| **场景** | 跨境汇款；投资组合再平衡 | 业务 | 待 |
| **平台** | 多租户（接入合作银行） | 平台 | 待 |
| **安全** | 渗透测试；红蓝对抗 | 安全 | 待 |

### 3.4 Q3-Q4 2027（v2.0+）：生态化

- 开放 API（白标给中小银行）
- 第三方 Agent 接入（Plugin Marketplace）
- 智能投顾完整版（接监管牌照）

## 4. 功能优先级矩阵

| 优先级 | 含义 | 示例 |
|--------|------|------|
| **P0** | 必须做（核心场景 + 合规底线） | 转账、卡片、对话、合规拦截 |
| **P1** | 重要（影响体验与商业价值） | 账单分析、理财 v1、HITL |
| **P2** | 锦上添花 | 主动建议、跨场景联动 |
| **P3** | 探索（验证价值后再排期） | 自适应学习 |

按 **价值 / 风险 / 合规** 综合评估：

| 功能 | 价值 | 风险 | 合规 | 优先级 |
|------|------|------|------|--------|
| 转账 v1 | 高 | 高 | 高 | P0 |
| 对话 v1 | 高 | 中 | 中 | P0 |
| 卡片管理 | 高 | 中 | 中 | P0 |
| 账单分析 | 中 | 低 | 低 | P1 |
| 理财 v1 | 中 | 高 | 高 | P1 |
| 订阅管理 | 中 | 中 | 中 | P1 |
| 跨场景联动 | 中 | 中 | 中 | P2 |
| 自适应学习 | 中 | 高 | 高 | P3 |

## 5. 关键依赖

| 依赖 | 来自 | 风险 | 缓解 |
|------|------|------|------|
| LLM 服务稳定性 | 外部 | 中 | 双供应商 + 缓存 + 降级 |
| 核心银行 CBS API | 行内 | 中 | 联调测试 + Mock |
| 监管报送通道 | 央行 | 低 | 提前沟通 |
| 算法备案 | 网信办 | 中 | 提前 3 个月准备 |
| 用户活跃度 | 业务 | 中 | MVP 早期用户运营 |

## 6. 非功能性目标（Target，需目标环境验证）

| 维度 | 目标 |
|------|------|
| **可用性** | 99.95%（生产） |
| **响应延迟** | 对话首响 ≤ 2s；转账确认 ≤ 500ms |
| **意图识别准确率** | ≥ 95%（黄金集） |
| **人工接管率** | ≤ 20%（v1.0）→ ≤ 10%（v1.5） |
| **合规拦截准确率** | ≥ 99%（漏判视为 P0 bug） |
| **审计日志完整率** | 100% |

---

## 7. 关键风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| **LLM 输出不合规** | 高 | 内容审查 + 兜底话术 + 人工接管 |
| **模型幻觉导致错误交易** | 高 | 强制 HITL + 服务端二次校验 |
| **数据泄露** | 高 | 分级加密 + 审计 + 监控 |
| **监管政策变化** | 中 | 持续跟踪 + 模块化合规 |
| **LLM 厂商服务中断** | 中 | 双供应商 + 降级到规则 |
| **团队人力瓶颈** | 中 | 文档化降低 onboarding 成本 |

---

## 8. 评审与更新

- **评审频率**：每月 1 次（月末周会）
- **触发更新**：重大里程碑完成 / 重大风险 / 战略调整
- **评审参与人**：全员
