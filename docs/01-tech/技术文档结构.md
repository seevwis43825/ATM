## 建议章节结构（15-25 页）

### 第 1 章　项目概述（2 页）

- 1.1 项目背景：传统银行 App 的操作路径冗长，用户完成一笔转账平均需要 6-8 步
- 1.2 产品定位：用自然语言对话替代菜单点击，让 Agent 理解意图并自主规划执行
- 1.3 场景覆盖：六大场景全覆盖（智能转账 / 账单分析 / 理财操作 / 卡片管理 / 订阅管理 / 跨场景联动）
- 1.4 创新点（3-4 条，这是评委最先看的）
  - 跨场景主动服务：不只是被动执行，而是主动发现用户遗忘的订阅、即将到来的生日
  - 可解释风控：所有风险判定规则透明可追溯，不同于黑盒模型
  - Agent 无执行权架构：模型只有发起权，资金操作必须用户显式授权

### 第 2 章　系统架构（4-5 页）

- 2.1 总体架构图（用五层架构图）
- 2.2 各层职责说明
  - 渠道层：Web 移动端 + 聊天窗 + 可视化卡片
  - Agent 大脑层：意图识别 → 任务规划 → 工具调用 → 结果生成
  - 业务工具层：六大场景工具集，统一契约
  - 数据层：Mock 数据（用户/流水/产品/卡片/订阅）
  - 安全层：风险分级 + 二次确认 + 审计日志
- 2.3 关键接口设计（贴 `/api/chat` 的请求响应示例）
- 2.4 数据流时序图（用户说一句话 → 到前端渲染卡片，完整链路）

### 第 3 章　核心算法说明（5-6 页，平台明确要求）

**3.1 意图识别**
- 方法：Few-shot 提示词工程 + 意图分类枚举
- 意图类别：`transfer` / `bill_analysis` / `wealth` / `card` / `subscription` / `compound`
- 说明多轮对话中的指代消解（"那再帮我转 200" 如何理解）
- 给出准确率数据（自己测 100 条语料）

**3.2 任务规划（Planner）**
- 复杂指令拆解：如"转 500 给张三并告诉我这个月花了多少" → 拆成两个步骤
- 规划流程：意图分解 → 依赖排序 → 顺序执行 → 结果聚合
- 给出伪代码或流程图

**3.3 异常交易识别算法**（重点，C 负责提供）
三条可解释规则，逐条说明：
1. **金额离群检测**：单笔金额 > 该用户历史交易的 95 分位 → 标记
2. **时间异常**：交易时间在 00:00-05:00 且金额 > 5000 → 标记
3. **地域/渠道异常**：首次出现的跨境渠道 或 收款方在风险名单 → 标记
- 给出触发阈值、计算方式、实测命中率

**3.4 理财风险匹配算法**（D 负责提供）
- 用户风险等级评估：问卷打分 → R1-R5
- 产品匹配规则：只推荐 ≤ 用户风险等级的产品
- 排序权重：收益率 40% + 流动性 30% + 历史波动 30%（说明权重来源）

**3.5 跨场景联动推理**（加分项，重点写）
- 触发机制：定时任务 + 事件驱动
- 案例：「生日前 2 天 + 账户活期 > 1000 元 → 提示锁定预算并推荐鲜花蛋糕」
- 说明如何避免过度打扰（频次控制）

### 第 4 章　安全设计（3-4 页）

- 4.1 权限分级模型（三级风险，引用安全自评报告）
- 4.2 二次确认机制：Agent 无执行权，只有发起权
- 4.3 数据脱敏策略：卡号/手机号/身份证的展示规则
- 4.4 审计日志设计：字段结构、存储方式、留存策略
- 4.5 隐私保护：用户数据不用于模型训练

### 第 5 章　工程实现（3-4 页）

- 5.1 技术选型与理由（为什么选这个框架）
- 5.2 代码结构说明（贴目录树）
- 5.3 部署方案（架构、环境要求、启动方式）
- 5.4 测试策略（单元测试 + 场景端到端测试）
- 5.5 团队协作工程化（Git 分支模型、契约驱动开发——这一点能体现工程素养）

### 第 6 章　总结与展望（1-2 页）

- 已完成成果
- 局限性（诚实说明）
- 未来演进方向

## 写作注意事项

1. **必须配图**：架构图、时序图、流程图至少各一张。纯文字的技术文档评委看不下去。
2. **代码片段要精简**：只贴关键 10-20 行，不要贴整个文件。
3. **数据要真实**：准确率、响应时间等要自己实测，不要编。
4. **统一术语**：全文统一用"Agent 大脑层""业务工具层"等称呼，不要一会叫"中台"一会叫"核心层"。
5. **导出格式**：用 Word 写完导出 PDF，检查中文字体是否正常显示。
