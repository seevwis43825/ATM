## 预设评委问答（务必准备）

| 可能的问题 | 建议回答方向 |
|---|---|
| **"你们的 Agent 会不会理解错意图转错账？"** | 讲二次确认机制：Agent 只有发起权没有执行权，所有资金操作必须用户点击确认，且确认卡片完整展示收款人和金额。同时有金额阈值拦截。 |
| **"和现有的银行智能客服有什么区别？"** | 智能客服是问答式（FAQ 检索），我们是**执行式**——理解意图后真的调工具完成操作，并且能跨场景主动发现需求。 |
| **"异常交易识别为什么不用机器学习？"** | 两个原因：一是金融场景要求可解释性，监管需要知道为什么判定异常；二是冷启动阶段样本不足。规则引擎准确率高且可审计，后续可叠加模型做补充。 |
| **"数据是真实的吗？"** | 坦诚说明是模拟数据，因为无法接入真实银行核心系统。但数据结构和业务流程完全按真实场景设计，且埋入了异常交易等测试用例。 |
| **"用了什么大模型？成本多少？"** | 说明调用的是兼容 OpenAI 协议的模型，并给出"意图识别用小模型、复杂规划用大模型"的分层策略来控制成本。（如果没实际接入 API，就说当前是 Mock 模式演示架构） |
| **"5 个人异地怎么做协作的？"** | 讲契约驱动开发：先冻结接口契约，然后 5 人并行开发互不阻塞。GitHub 分支保护 + 每日站会 + 轮值清道夫。**这个问题答好能加分，体现工程素养。** |
| **"如果要接入真实银行系统，需要改造什么？"** | 数据层替换、增加交易冲正与对账、补充多因素认证、审计日志加防篡改签名、通过等保测评。 |
| **"你们的创新点本质是什么？"** | 从"人适应系统"到"系统适应人"。传统银行数字化是让人学会用 App，我们是让系统学会听懂人。 |

## 制作建议

1. **不要堆文字**：每页 ≤ 5 行字，多用图。评委看的是你讲，不是读 PPT。
2. **统一视觉**：配色不超过 3 种，字体统一。建议用深色底 + 亮色强调，科技感强。
3. **截图要清晰**：所有界面截图用高分屏截，不要用手机拍屏幕。
4. **加页码和进度条**：让评委知道还剩多少。
5. **准备 Demo 兜底视频**：万一会场网络不通，用录好的视频替代现场演示。
6. **导出三个格式**：PPTX（可编辑）+ PDF（保险，字体不会乱），两个都传。
