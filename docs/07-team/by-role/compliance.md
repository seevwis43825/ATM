## 1. 你是什么

你是 5 人团队里**确保不出事**的人。你不写业务代码，但你**否决**不安全的代码。你的存在让：

- 用户的 PII 不被泄露
- 资金不被错转
- 监管检查能过
- 团队不踩法律红线

你必须**懂法规 + 懂技术 + 懂业务**三者的交叉点。

## 4. 你的"硬规则"（必须为的）

### 4.1 业务侧红线（业务开发必须遵守）

1. **不收集 PII 没有合法基础**（《个保法》第 13 条）
2. **不处理敏感 PII 没有单独同意**（第 28-29 条）
3. **不做自动化决策不告知**（第 24 条）
4. **不响应用户数据请求**（第 46-47 条）— 系统必须提供接口
5. **数据不出境没评估**（《数据安全法》第 36 条）
6. **网络日志不留 ≥ 6 个月**（《网络安全法》第 21 条）
7. **不报反洗钱大额交易**（《反洗钱法》第 20 条）
8. **不处理 PIA 上线新功能**（央行 AI 指导意见）

### 4.2 技术侧红线

1. **明文存储 L4 数据**（密码、CVV、生物特征）
2. **日志中出现明文 PII**（身份证、银行卡、手机号）
3. **审计日志可被修改/删除**
5. **API 不鉴权或鉴权绕过**
6. **数据导出无审批无加密**
7. **DB 账号权限过大**（DBA 账号给业务）
8. **密钥硬编码或 git 提交**

### 4.3 你的"一票否决"权

以下情况你可以直接 **Block 上线**：

- [ ] 涉及 PII 但无 PIA
- [ ] 数据未分级
- [ ] 审计埋点缺失
- [ ] 合规拦截被绕过
- [ ] LLM Prompt 含合规风险
- [ ] 用户权利接口缺失

## 7. PIA（个人信息影响评估）流程

每个新功能上线前的必走流程（详见 [`05-security-compliance/02-compliance-matrix.md` §9](../../05-security-compliance/02-compliance-matrix.md)）：

```
1. 产品/业务起草 PIA
   ↓
2. 你（合规角色）Review
   ├─ 高风险 → 详细 PIA + 缓解措施
   ├─ 中风险 → 简化 PIA + Checklist
   └─ 低风险 → 备案即可
   ↓
3. 架构师 Review（架构落地）
   ↓
4. 业务开发实施
   ↓
5. 上线前合规 Checklist 勾选
   ↓
6. 上线后 1 个月回访
```

## 12. 数据泄露应急

如发生数据泄露（**P0 事故**），24h 内必须完成：

1. **0-2h**：保留证据 + 初步评估
2. **2-8h**：评估范围（用户数、PII 类型）
3. **8-24h**：通知架构师 + 法务 → 决策是否报监管
4. **24-72h**：通知受影响用户 + 报送网信办（如触发）
5. **72h-1w**：完整调查报告 + 改进措施

详见 [`04-operations/03-incident-response.md` §5.4](../../04-operations/03-incident-response.md)

## 15. FAQ

### Q1：业务开发嫌合规麻烦怎么办？

耐心 + 强硬。合规是底线，不是可选项。如果业务开发不理解，用**事故案例**教育（参考同业数据泄露罚款）。

### Q2：PIA 模板怎么填？

详见 [`05-security-compliance/02-compliance-matrix.md` §9](../../05-security-compliance/02-compliance-matrix.md)。如有疑问，问架构师 + 我（合规）。

### Q3：法规更新怎么办？

跟踪 → 评估影响 → 更新合规矩阵 → 通知架构师 + 业务开发。重要法规更新 → 月度合规 review + 全员培训。

### Q4：监管来检查怎么办？

- 提前 1 周准备合规证据包
- 全员配合（你主导）
- 24h 内提交初步资料
