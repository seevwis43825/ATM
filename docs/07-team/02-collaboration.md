# 协作机制（Collaboration）

> **状态**：评审中 · **所有者**：架构师 · **版本**：v1.0
> **最后更新**：2026-10-01

---

## 1. 目的

建立 5 人小团队的**高效协作机制**：

1. 让会议成为推进器，不是负担
2. 让异步沟通（文档/Issue）成为主要工作方式
3. 让值班、决策、冲突解决有据可依

## 3. 会议体系

### 3.1 会议日历（每周）

| 会议 | 频率 | 时长 | 参与人 | 议程 |
|------|------|------|--------|------|
| **Daily Standup** | 每日 | 15min | 全员 | 昨天做了什么 / 今天做什么 / 卡点 |
| **迭代规划** | 双周一 | 1h | 全员 | 下迭代工作项 + 优先级 |
| **迭代复盘** | 双周一 | 1h | 全员 | 上迭代做得好的 / 改进点 |
| **架构评审** | 按需 | 1h | 架构师 + 相关方 | RFC 评审 |
| **事故复盘** | 事故后 48h 内 | 1h | 涉及方 | Postmortem |
| **月度回顾** | 月末 | 2h | 全员 | 路线图 Review + 战略对齐 |
| **On-call 交接** | 每周一 | 15min | On-call | 值班交接 + 重点关注 |

### 3.2 Daily Standup 规则

**时间**：每日上午 10:00（固定）
**形式**：站立会议（视频必须开），15 分钟内必须结束
**发言**：每人 1 分钟，说三件事：
1. 昨天完成了什么
2. 今天计划做什么
3. 有什么卡点（需要谁帮助）

**卡点处理**：会后单独拉人解决（不在 standup 上展开讨论）。

### 3.3 异步优先原则

**默认异步**：能用文档/Issue/PR 解决的事情，不要开会。

**何时开会**：
- ✅ 需要多方讨论权衡（如架构决策）
- ✅ 紧急事故
- ✅ 重要对齐（季度规划）
- ✅ 头脑风暴

**何时不开会**：
- ❌ 进度同步（看 Dashboard）
- ❌ 答疑（异步讨论）
- ❌ 信息通告（写文档）

### 3.4 会议效率规则

- 必须提前 24h 发议程
- 必须有产出（决议 / Action Item）
- 会议纪要 24h 内发布
- 超过 50% 时间还在讨论 → 转为异步

## 4. 异步沟通规范

### 4.0 当前代码协作基线

1. 从最新 `main` 创建 `feature/*`、`fix/*` 或 `docs/*` 短分支。
2. 通过 PR 合回 `main`；当前不从 `dev` 开分支，也不把 PR 提交到 `dev`。
3. 至少 1 人批准、CI 全绿；契约、安全、数据库和插件边界变更增加对应角色评审。
4. PR 描述列出变更、验证结果、风险和关联 Issue；测试数字引用本次运行输出。

### 4.1 Issue / Ticket

每个工作项必须有 Issue：

```markdown
标题: [模块] 简述
类型: Feature | Bug | Refactor | Docs | Compliance
优先级: P0 | P1 | P2 | P3
负责人: @xxx
关联文档: [链接]

## 背景
为什么做

## 验收标准
- [ ] 标准 1
- [ ] 标准 2

## 备注
[其他]
```

### 4.2 PR Review SLA

| 优先级 | 期望响应 | 期望完成 |
|--------|---------|---------|
| P0 | ≤ 4h | ≤ 24h |
| P1 | ≤ 8h | ≤ 3d |
| P2 | ≤ 24h | ≤ 1w |
| P3 | ≤ 48h | ≤ 2w |

详见 `03-development/03-pr-review-checklist.md`。

### 4.3 文档协作

- 重要决策必须形成文档（ADR）
- 文档 Review 用 PR（与代码一致）
- 文档 Reviewer 在文件头部记录

### 4.4 沟通频道

| 频道 | 用途 | 噪音 |
|------|------|------|
| `#general` | 日常闲聊、公告 | 接受 |
| `#dev` | 技术讨论 | 接受 |
| `#incident` | 事故响应（事故期间） | 集中 |
| `#oncall` | On-call 专用 | 值班期 |
| `#compliance` | 合规相关 | 集中 |

## 5. 决策机制

### 5.1 决策分级

| 类型 | 示例 | 决策者 |
|------|------|--------|
| **日常** | 代码细节、bug 修复 | PR Author + Reviewer |
| **战术** | 单模块设计、API 调整 | 模块 Owner |
| **战略** | 架构选型、技术栈变更、合规设计 | 全员 + 架构师终裁 |
| **紧急** | 事故处理、回滚 | IC（事故指挥官）|

### 5.2 反对意见处理

- 任何成员可以提异议
- 异议须有依据（数据 / 案例 / 法规）
- 异议不解决不进入实施
- 架构师对战略决策有最终决定权
- 反对意见记录在 ADR 中（即使最终未采纳）

### 5.3 RFC（Request for Comments）

重大变更走 RFC：

```
[RFC-001] 标题

## 摘要
一段话说清

## 背景
为什么做

## 方案
- 方案 A（推荐）
- 方案 B
- 方案 C

## 取舍
各方案的优劣

## 决策
最终选择 + 理由

## 影响
- 模块边界
- 合规 / 安全
- 性能 / 成本
- 时间
```

RFC 可在仓库文档、Issue 或团队统一协作平台发起；评论期由变更风险决定，最终决策写入 ADR，避免把未选定的平台或固定时限冒充当前门禁。

## 6. On-call 排班

### 6.1 排班规则

- 5 人，每人值班 7×24 一周
- 每月 25 号前发布下月排班
- 值班人不可连续值班两周（避免疲劳）

### 6.2 值班职责

- 5 分钟内响应告警（飞书/钉钉）
- 必要时升级（参见事故响应）
- 每日 18:00 在 `#oncall` 群发值班日报

### 6.3 值班日报模板

```markdown
# On-call 日报 YYYY-MM-DD

## 告警
- [HH:MM] <告警名>（P1/P2），已处理/仍在跟进
- ...

## 待跟进
- [ ] <Issue 链接>

## 系统健康
- API P99: 234ms ✅
- 错误率: 0.12% ✅
- LLM 错误率: 1.5% ✅
```

### 6.4 调休

- 值班期间被叫醒处理事故 ≥ 1 次 → 次日可晚到 1 小时
- 值班期间被叫醒 ≥ 3 次 → 调休 0.5 天

## 7. 冲突解决

### 7.1 优先级

- **合规 > 安全 > 业务 > 体验 > 性能 > 优雅**
- 合规问题一律 P0
- 安全问题一律 P0/P1

### 7.2 冲突场景

| 场景 | 处理 |
|------|------|
| 业务 vs 合规 | 合规赢，业务让步或征合规 |
| 业务 vs 技术 | 架构师仲裁，看长期影响 |
| 个人风格 vs 团队规范 | 团队规范赢，PR Review 引导 |
| 紧急 vs 流程 | 紧急先保一线（hotfix 例外），事后补流程 |

## 8. 远程协作

### 8.1 5 人默认远程 / 在家办公

- 核心时段（10:00-17:00）必须可联系
- 会议默认开视频
- 异步为主（文档、Issue、PR）

### 8.2 远程工具

- 视频会议（必开）
- 共享屏幕（默认）
- 文档协作（实时编辑）
- IM 已读回执（重要消息必须确认已读）

### 8.3 团队凝聚

- 每月 1 次线下（可选）
- 季度 1 次集中工作（Team Building）
- 飞书生日提醒 + 节日问候

## 9. 学习与成长

### 9.1 Tech Talk

- 每 2 周 1 次，30 分钟
- 主题：技术分享 / 论文解读 / 事故复盘 / 法规更新
- 轮流主讲

### 9.2 培训资源

- 公司报销书籍、培训费
- 季度 ≥ 1 次外部培训
- 会议内容录像归档（飞书/钉钉）

### 9.3 知识沉淀

- 每次 Tech Talk 输出 1 篇博客/文档
- 重大事故形成 Postmortem 文档
- 新人入职 Onboarding（详见 `07-team/03-onboarding.md`）

## 10. 绩效考核（参考维度）

| 维度 | 权重 |
|------|------|
| 交付质量（Bug 率、PR 质量）| 30% |
| 系统稳定性（MTTR、事故数）| 20% |
| 合规贡献（PIA 完成、安全发现）| 15% |
| 协作（PR Review、Tech Talk）| 15% |
| 学习成长（新技能、文档贡献）| 10% |
| 主动性（发现问题、改进建议）| 10% |

## 11. 工作时间

- **核心时段**：10:00 - 17:00
- **弹性**：±2 小时（9-11 点 / 16-19 点）
- **休息**：周末双休、国家法定假日
- **加班**：
  - 发布日 / 事故响应：必须
  - 紧急需求：协商
  - **不鼓励** 长期加班（健康优先）
