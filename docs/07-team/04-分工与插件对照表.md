# 分工与插件对照表

> **用途**：全队唯一的分工事实源。谁负责哪个插件 / 哪个模块，一查即知。
> **原则**：与代码一致 —— 本表由仓库实际内容推导，不是规划稿。
> **最后更新**：2026-09-28

---

## 1. 一句话结论

系统 = **1 个宿主 + 1 个框架层 + 1 个契约层 + 4 个业务插件 + 1 个模拟银行**。
"加一个业务场景" = 加一个插件，**不需要改宿主**（已实测：模板生成的插件从零到可路由，未改动宿主代码）。

## 5. 新增一个插件时的完整责任清单

> 漏掉任何一项都不会报错，插件只是**静默不生效**。这是本项目最容易踩的坑。

| # | 动作 | 漏掉的后果 | 负责人 |
|---|---|---|---|
| 1 | `dotnet new banking-plugin` 生成骨架 | — | 插件作者 |
| 2 | 在 `src/BankingAgent.slnx` 的 `/plugins/` 段登记项目 | 不参与本地与 CI 构建 | 插件作者 |
| 3 | 在 `BankingAgent.Host.csproj` 的 `PluginArtifact` 列表补一行 | DLL **永远不会**被复制进宿主 `plugins/` 输出目录 | 插件作者 |
| 4 | 需要落库时注册 `IEntitySetContributor` | 表不会被创建 | 插件作者 |
| 5 | 声明 `SupportedIntents` | 出现在 `/api/plugins/agents` 却永远收不到请求 | 插件作者 |
| 6 | 更新本表 §2 插件对照表 | 分工失真 | 插件作者 |
| 7 | 在 `.github/CODEOWNERS` 补路径 | PR 不会通知到 owner | 架构师 |
| 8 | 跑 `PluginValidator` 过门禁 | CI 会拦住 | 插件作者 |

### 5.1 自检命令

```bash
# 从仓库根目录
dotnet build src/BankingAgent.slnx -c Release          # .slnx 需要 SDK 9.0.200+
dotnet run --project src/PluginValidator -- src/src/BankingAgent.Host/bin/Release/net8.0/plugins
dotnet test src/UnitTests/UnitTests.csproj
```

预期：构建 0 警告；校验器 `*** 校验通过 ***`（退出码 0）；单测 143 通过。

> ⚠️ **构建配置必须与启动配置一致**：`PluginArtifact` 是 `Exists` 条件的。
> 用 `-c Release` 编译却用默认的 `dotnet run`（Debug）启动，宿主的
> `plugins/` 输出目录会是空的 —— 不报错，只是什么插件都没加载。
> 启动请显式加 `-c Release`。
