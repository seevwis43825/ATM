# 远程协作 SOP（5 人异地版）

> 核心矛盾：**5 个人，不同地方，还要合出一个项目。**
> 解法：把"人之间的同步"降到最低，把"代码之间的同步"交给自动化。

---

## 一、三层同步机制

### 第 1 层：代码同步（自动化，无需沟通）

GitHub 私有仓库是唯一真相来源。规则：

- **分支命名**：`feature/转账-张三`、`fix/账单图表`、`docs/安全报告`
- **提交信息**：`feat(transfer): 支持按手机号转账` — 类型(模块): 做了什么
- **每日必推**：哪怕没写完，推到自己的 feature 分支（不是 main），别人能看到进度
- **合并**：一律走 Pull Request，至少 1 人 review 通过才能进 main

### 第 2 层：接口同步（契约文件，每周一次会）

`banking-core/contracts/agent-tool-contract.md` 是唯一的接口说明书。
**任何人不需要问别人"你那个函数叫什么"——看契约文件。**

同步节奏：
- 每天 21:30 自动跑一次契约检查（脚本会对比代码里的函数签名和契约文件是否一致）
- 不一致就在群里 @ 对应的人

### 第 3 层：人的同步（短会，每天 15 分钟）

**每晚 21:00，腾讯会议，站着开，15 分钟封顶。**

固定三句话模板（每人 1 分钟，不展开讨论）：
1. 昨天我完成了什么（贴 commit 链接）
2. 今天我卡在哪（贴报错截图）
3. 我需要谁配合

> 卡住超过 2 小时的事，**不要自己硬磕**，直接丢群里。异地协作最大的杀手不是技术难题，是"不好意思问"。

---

## 二、角色轮值（避免异地拖沓）

| 角色 | 人选 | 职责 |
|---|---|---|
| 项目经理 | A | 排期、催进度、裁决契约变更 |
| 轮值记录员 | 每周轮换 | 写会议纪要，发群里，同步到 GitHub Issue |
| 轮值"清道夫" | 每周轮换 | 专门处理别人的报错和环境问题，本周不写自己的功能 |

**清道夫机制是异地协作的关键**：总有人环境跑不起来、依赖装不上，如果没有专人负责，会拖垮进度。

---

## 三、环境一致性（最大的坑）

异地协作 80% 的混乱来自"我这能跑，你那不能跑"。对策：

1. **`.env.example` 入库，`.env` 不入库** — 每个人的 key 自己填
2. **Node 版本锁死** — 在 `package.json` 写 `"engines": { "node": ">=20" }`
3. **MOCK_MODE 默认开启** — 没有 key 的人也能跑通全流程
4. **一键脚本** — `scripts/dev.sh` 同时起前后端，避免手动开两个终端搞错端口

---

## 四、任务看板（GitHub Projects）

用 GitHub 项目看板，5 列：

```
Backlog → This Week → In Progress → Review → Done
```

规则：
- 每个 Issue 必须打标签：`场景:转账` / `角色:A` / `类型:功能`
- 认领任务 = 把自己 assign 上，**不要口头认领**
- 每天站会前把卡片挪到正确位置

---

## 五、文件/资料共享

| 内容 | 存放位置 | 原因 |
|---|---|---|
| 代码、文档、PPT 源文件 | GitHub 仓库 | 版本可追溯 |
| 大文件（视频、录屏素材） | 百度网盘/夸克网盘，群里贴链接 | 仓库有 300MB 限制 |
| 设计稿、截图 | 群里直接发 | 用完即弃 |
| 会议纪要 | GitHub Issue + 群里同步 | 可搜索 |

> **注意**：最终提交的 ZIP 不超过 300MB。视频 500MB 是单独上传的通道，不要塞进代码 ZIP。

## 六、关键时间节点提醒（设为手机闹钟）

| 时间 | 事项 |
|---|---|
| 每周日 20:00 | 周计划会（1 小时），定下周任务 |
| 每天 21:00 | 站会（15 分钟） |
| 10.23 | 文档初稿必须全部完成 |
| 10.30 | 演示视频拍摄完成 |
| 11.3 | 全队彩排答辩 |
| 11.6 | **提交日，上午 10 点前务必上传完毕** |

> 最后一条尤其重要：**不要卡在 11.6 当天提交**。平台可能拥堵，提前一天完成上传，11.6 只做检查。
