## 一、部署边界

当前可复现的交付路径是 Windows、macOS 或 Linux 本机运行：

```text
浏览器
  └─ BankingAgent.Host :5243
       ├─ 内置 wwwroot 控制台
       ├─ Agent API 与 SQLite
       └─ 调用 MockBank.Api :5200
```

当前没有独立前端构建，也没有 Node 服务。默认不依赖外部数据库、Docker、Python、Redis、Kafka 或 AI Key。

公网/生产部署尚未完成：仓库没有现成 Dockerfile、Docker Compose、Kubernetes 清单、云平台 IaC、反向代理配置、域名证书方案或自动发布流水线。因此本文不承诺可用公网地址，也不把架构蓝图写成已部署能力。

## 二、本地演示部署（已验证）

### 1. 前置条件

- .NET SDK 9.0.200+，用于 `src/BankingAgent.slnx`
- .NET 8 Runtime 与 Targeting Pack，项目目标框架为 `net8.0`

本机验证环境示例：SDK 9.0.305、.NET Runtime 8.0.20。其他满足要求的补丁版本也可使用。

```powershell
dotnet --version
dotnet --list-runtimes
```

### 2. Release 编译

从仓库根目录执行：

```powershell
dotnet restore src/BankingAgent.slnx
dotnet build src/BankingAgent.slnx -c Release
```

必须使用 Release 编译和 Release 启动。混用 Debug/Release 会导致宿主扫描不到插件。

### 3. 检查插件产物

```powershell
$pluginDir = "src/src/BankingAgent.Host/bin/Release/net8.0/plugins"
$required = @(
  "BankingAgent.Plugin.Transfer.dll",
  "BankingAgent.Plugin.BillAnalysis.dll",
  "BankingAgent.Plugin.CardManagement.dll",
  "BankingAgent.Plugin.Wealth.dll"
)

$missing = $required | Where-Object {
  -not (Test-Path (Join-Path $pluginDir $_))
}
if ($missing) { throw "缺少插件 DLL：$($missing -join ', ')" }
```

### 4. 启动两个进程

打开两个 PowerShell 终端，均从仓库根目录启动。

终端 1：

```powershell
dotnet run --project src/mock-bank/MockBank.Api -c Release
```

终端 2：

```powershell
dotnet run --project src/src/BankingAgent.Host -c Release
```

启动后访问：

- MockBank 健康检查：<http://localhost:5200/health>
- Host 健康检查：<http://localhost:5243/health>
- 内置控制台：<http://localhost:5243>

PowerShell 验证：

```powershell
Invoke-RestMethod http://localhost:5200/health
Invoke-RestMethod http://localhost:5243/health
```

### 5. 停止

在两个前台终端分别按 `Ctrl+C`。若终端已丢失：

```powershell
Get-NetTCPConnection -LocalPort 5200,5243 -State Listen |
  Select-Object LocalPort, OwningProcess

# 确认 PID 对应本项目后再执行
Stop-Process -Id <PID>
```

## 四、端口冲突排查

```powershell
Get-NetTCPConnection -LocalPort 5200,5243 -State Listen |
  Select-Object LocalAddress, LocalPort, OwningProcess
Get-Process -Id <PID>
```

确认是残留实例后停止该进程。若必须更换端口，启动命令可追加 `--urls`，但修改 MockBank 端口时还必须同步设置宿主的 `CoreBank__BaseUrl`：

```powershell
# 示例：仅用于临时联调
$env:CoreBank__BaseUrl = "http://localhost:6200"
dotnet run --project src/mock-bank/MockBank.Api -c Release -- --urls http://localhost:6200
dotnet run --project src/src/BankingAgent.Host -c Release
```

演示交付建议保持默认 5200/5243，减少配置偏差。

## 五、常见故障

### `.slnx` 无法加载

当前 SDK 低于 9.0.200。升级 SDK 后重新执行 `dotnet --version`。

### 编译成功但运行提示缺少 .NET 8

`.slnx` 由 SDK 9 读取，应用本身目标为 `net8.0`。安装 .NET 8 Runtime；缺少引用程序集时安装 .NET 8 SDK 或 Targeting Pack。

### 插件未加载或提示依赖插件不存在

检查是否遗漏 `-c Release`，并确认以下目录中的四个 DLL：

```text
src/src/BankingAgent.Host/bin/Release/net8.0/plugins/
```

重新执行完整解决方案 Release 编译，不要只编译宿主项目。

### Host `/health` 失败

宿主健康检查包含数据库真实探活。检查启动日志、SQLite 文件目录写权限，并确认工作目录没有只读限制。

### Host 无法调用 MockBank

先访问 <http://localhost:5200/health>。若失败，检查 MockBank 进程和端口；若改过端口，确认 `CoreBank__BaseUrl` 与实际地址一致。

## 六、可选增强

### 大模型

默认规则表无需密钥。需要增强意图识别时，可在启动 Host 的同一终端设置：

```powershell
$env:Ai__ApiKey = "sk-xxx"
dotnet run --project src/src/BankingAgent.Host -c Release
```

AI Key 只能作为可选增强，不是部署前置条件，不得提交到仓库。

### PostgreSQL

当前已验证的本地路径使用 SQLite。代码包含 PostgreSQL Provider，但切换到 PostgreSQL 属于生产化演进，需要自行准备数据库、迁移、备份、连接密钥与网络策略；不能据此认定生产部署已完成。
